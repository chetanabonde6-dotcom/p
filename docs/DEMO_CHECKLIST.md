# Final demo checks

Mark only checks someone has actually performed.

- [ ] Main flow satisfies the exact problem statement and a judging requirement.
- [ ] Main buttons, navigation, forms, and filters work.
- [ ] Required-input validation and success feedback work where applicable.
- [ ] Loading, empty, error, and retry/reset states are understandable.
- [ ] Mock data is labelled; live API failures never show fake success.
- [ ] Phone and presentation-laptop layouts are usable.
- [ ] Text, labels, keyboard access, and focus are clear.
- [ ] There are no known demo-blocking build or console errors.
- [ ] A required public app link has been checked; a repository URL is not an app URL.
- [ ] Latest source and run instructions are downloaded.
- [ ] Backup local run/screenshots/recording of the actual flow is ready.
- [ ] The team knows which features are real, mocked, or unfinished.
- [ ] New features are frozen for the final 30 minutes.

## Two-minute explanation

0:00–0:20: Who our user is, their problem, and the outcome our app provides.
0:20–1:10: Show the actual main flow from input to useful result/confirmation.
1:10–1:35: Explain your actual frontend work: screens, interactions, responsive layout, and API connection if implemented.
1:35–2:00: Explain current limitations, real versus mock data, and one next improvement.

## Practise these questions

1. Why did you choose this user and flow?
2. What happens when the main button is clicked?
3. Which parts call the real backend?
4. What happens when the API fails or no results exist?
5. How did you check phone usability?

Ask ChatGPT to answer from the actual code. Understand the answers and acknowledge AI assistance honestly if asked.
